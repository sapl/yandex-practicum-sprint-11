# Задание 2: Разделение на домены и потоки данных

Используя подход Data Mesh для обеспечения масштабируемости и гибкости мы разделяем систему на следующие домены:

### Выделенные домены

| Домен                | Назначение                                                                 |
|----------------------|----------------------------------------------------------------------------|
| **Медицинский**      | Данные пациентов, обращения, услуги, расписания, интеграция с ИИ-сервисами |
| **ИИ-сервисы**       | Анализ медицинских данных, обучение моделей, обработка изображений         |
| **Финансовый**       | Банковские счета, кредиты, транзакции, интеграция с финтех-сервисами       |
| **Фармацевтический** | Инвентарь медикаментов, закупки, поставки                                  |
| **Оборудование**     | Учёт и управление оборудованием, обслуживание, IoT-данные                  |
| **BI/Аналитика**     | Централизованная витрина данных для построения отчётности                  |
| **Интеграционный**   | Слой взаимодействия между доменами (Kafka/API Gateway + трансформации)     |
| **Legacy DWH**       | Архивная часть, источник для миграции, не используется для новой логики    |

## Преимущества выделения доменов

- **Независимое масштабирование**: каждая команда может развивать свой домен без зависимости от DWH.
- **Упрощённая поддержка**: меньше связей и бизнес-логики в монолите.
- **Гибкость в выборе технологий**: каждый домен может использовать подходящий стек.
- **Быстрое добавление новых бизнесов**: например, фарма и производство легко интегрируются в общую архитектуру.
- **Отказ от легаси-логики в DWH**: DWH будет использоваться только для хранения исторических данных.

## Потоки данных (DFD)

См. диаграмму: [dfd_architecture.puml](dfd_architecture.png)

- Данные пациентов → Медицинский домен
- Медицинские данные ↔ ИИ-домен
- Финансовые транзакции → Финансовый домен
- Сводная аналитика → BI-домен (через витрину)
- Инвентаризация → Фармацевтический + Оборудование
- События и взаимодействия → Через интеграционную шину (Kafka / Event Bus / Debezium)
