# Задание 1 - Архитектура системы через год

## Проблемные места

| Проблема                                         | Описание                                                                        | Последствия                                                                   |
|--------------------------------------------------|---------------------------------------------------------------------------------|-------------------------------------------------------------------------------|
| Монолитный DWH с бизнес-логикой                  | SQL Server 2008 содержит всю бизнес-логику, тормозит развитие новых направлений | Высокая сложность изменений, узкое горлышко, невозможность масштабировать DWH |
| Старые технологии интерфейсов (Power Builder)    | Устаревший интерфейс для операторов клиник                                      | Сложность поддержки, нет масштабируемости, плохая UX                          |
| Apache Camel как шина                            | Не масштабируется, сложно адаптировать под новые сервисы                        | Повышенные затраты на интеграции                                              |
| BI-система работает поверх DWH                   | Большое количество трансформаций, долгий рендер отчётов                         | Снижение производительности и доверия к аналитике                             |
| Сырые данные и подготовыленные в общем хранилище | Доступ к готовым данным осложняется общей нагрузкой на сервер DWH               | Долгая работа, сложность выделения важных данных                              |
| Отсутствие витрины данных                        | Нет единого и удобного способа доступа к данным                                 | Удлиняется TTM, ручной труд аналитиков, дублирование логики                   |
| Нет изоляции между доменами                      | Все бизнесы используют общий слой бизнес-логики и БД                            | Высокая сложность изменений, узкое горлышко, невозможность масштабировать DWH |
| 


## Приоритизация (метод MoSCoW)

- **Must Have**:
    - Разделить сырые данные и подготовленные
    - Разделение данных по доменам
    - Создание витрины данных с разграничением доступа
    - Вынесение бизнес-логики из DWH
    - Замена устаревшей шины интеграции

- **Should Have**:
    - Упрощение интерфейса доступа к BI (Удобные витприны, API, self-service)
    - Отказ от Power Builder

- **Could Have**:
    - Оптимизация хранения истории изменений
    - Data discovery и автоматизация 

- **Won’t Have (сейчас)**:
    - Миграция всех медицинских данных в real-time Lakehouse (отложено до финального этапа)

### Используем подход Data Mesh

- **Данные = продукт** — каждый домен (например, Финтех, Медицина, Электроника) владеет и отвечает за свои датасеты.
- **Децентрализация хранения и доступа**: отказ от единого монолитного DWH в пользу дата-озёр, витрин и отдельных хранилищ по доменам.
- **Использование современных инструментов хранения и анализа данных**: S3, Iceberg, ClickHouse, BI-витрины.
- **Внедрение портала самообслуживания**: создание и просмотр отчётов в удобной форме без участия тех. специалистов.
- **Поддержка каталогизации и открытие доступа через API Gateway**.


### Компоненты 

| Компонент            | Технология           | Назначение                                                              |
|----------------------|----------------------|-------------------------------------------------------------------------|
| **Legacy DWH**       | Microsoft SQL Server | Исторические данные, сырые данные                                       |
| **Интеграция**       | Kafka, Debezium      | Интеграция/обмен данных, Debezium - для интеграции с Legacy |
| **Data Lake**        | S3 + Apache Iceberg  | Хранение сырых данных, неструктурированных, файлы (снимки)              |
| **OLAP-хранилище**   | ClickHouse           | Агрегаты и аналитика для BI-витрин                                   |
| **Витрины**          | Metabase, Grafana    | BI-интерфейс по доменам, Grafana для мониторинга и технических бордов   |
| **Портал**           | Web App              | Конструктор отчётов и самообслуживание                                  |
| **API Gateway**      | Spring Boot          | Централизованный доступ к данным                                        |
| **Каталог данных**   | Web App + REST API   | Навигация и описание доступных датасетов                                |
| **Доменные сервисы** | Python / Java/Kotlin | Обработка и публикация данных в доменах                                 |
